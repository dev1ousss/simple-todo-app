# Fullstack Todo App

Веб-приложение для управления задачами и категориями. Проект развернут на базе асинхронного бэкенда **FastAPI**,
реляционной базы данных **PostgreSQL** и современного фронтенда на **Node.js**. Вся экосистема полностью
контейнеризирована.

## Быстрый запуск

Для локального запуска всей экосистемы (базы данных, бэкенда и фронтенда) вам понадобится только установленный
инструмент **Docker** с поддержкой Compose.

### 1. Клонируйте репозиторий на свой компьютер

```bash
git clone https://github.com/dev1ousss/simple-todo-app.git
```

### 2. Перейдите в корневую папку проекта

```bash
cd simple-todo-app
```

### 3. Запустите контейнеры одной командой

```bash
docker compose up --build
```

### 4. Дождитесь автоматической инициализации

Оркестратор сам выполнит все необходимые шаги:

1. Запустит изолированное хранилище PostgreSQL (`sta_container`) и выделит том для персистентности данных.
2. Проверит утилитой `pg_isready` готовность СУБД отвечать на TCP-запросы.
3. Соберет и поднимет образ асинхронного бэкенда FastAPI.
4. Развернет клиентскую часть Node.js с поддержкой живой перезагрузки (`WATCHPACK_POLLING=true`).

## Документация API (Контракты эндпоинтов)

Приложение предоставляет следующие REST эндпоинты для интеграции с фронтендом:

### 1) Получить список задач (`GET /tasks`)

Тело запроса: **отсутствует**.

Ожидаемый ответ:

* **Статус**: `200 OK`
* **Тело ответа**: JSON-массив задач

```json
[
  {
    "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "title": "Сделать ДЗ",
    "completed": false
  },
  {
    "id": "f4d8d97d-27b2-4f74-9c14-f1f8ee9b9d4f",
    "title": "Проверить PR",
    "completed": true
  }
]
```

Если задач нет:

```json
[]
```

### 2) Создать задачу (`POST /tasks`)

Тело запроса:

```json
{
  "title": "Подготовить урок"
}
```

Ожидаемый ответ:

* **Статус**: `201 Created`
* **Тело ответа**: созданная задача

```json
{
  "id": "b1b3d9d7-7d47-4f30-a9f6-9dce7d8f43d2",
  "title": "Подготовить урок",
  "completed": false
}
```

### 3) Обновить задачу (`PATCH /tasks/{id}`)

* **id** в path-параметре: строковый UUID.
* **Тело запроса**: только изменившиеся поля (одно или несколько).

Если поменялся только `title`:

```json
{
  "title": "Подготовить урок по REST"
}
```

Если поменялся только `completed`:

```json
{
  "completed": true
}
```

Если поменялись оба поля:

```json
{
  "title": "Подготовить урок по REST",
  "completed": true
}
```

Ожидаемый ответ:

* **Статус**: `200 OK`
* **Тело ответа**: обновленная задача

```json
{
  "id": "b1b3d9d7-7d47-4f30-a9f6-9dce7d8f43d2",
  "title": "Подготовить урок по REST",
  "completed": true
}
```

### 4) Удалить задачу (`DELETE /tasks/{id}`)

* **id** в path-параметре: строковый UUID.
* **Тело запроса**: **отсутствует**.

Ожидаемый ответ:

* **Статус**: `204 No Content`
* **Тело ответа**: **отсутствует**

### 5) Получить список категорий (`GET /categories`)

Тело запроса: **отсутствует**.

Ожидаемый ответ:

* **Статус**: `200 OK`
* **Тело ответа**: JSON-массив категорий

```json
[
  {
    "id": "fbbf0f30-c8e8-4a5f-a9c7-2cf5b29b9a0d",
    "name": "Учеба"
  },
  {
    "id": "eb455b06-6c8d-4d5d-8d76-4a0a857ff2e4",
    "name": "Работа"
  }
]
```

Если категорий нет:

```json
[]
```

### 6) Создать категорию (`POST /categories`)

Тело запроса:

```json
{
  "name": "Учеба"
}
```

Ожидаемый ответ:

* **Статус**: `201 Created`
* **Тело ответа**: созданная категория

```json
{
  "id": "fbbf0f30-c8e8-4a5f-a9c7-2cf5b29b9a0d",
  "name": "Учеба"
}
```

### 7) Обновить категорию (`PATCH /categories/{id}`)

* **id** в path-параметре: строковый UUID.
* **Тело запроса**: только изменившиеся поля.

Если поменялось название:

```json
{
  "name": "Домашние дела"
}
```

Ожидаемый ответ:

* **Статус**: `200 OK`
* **Тело ответа**: обновленная категория

```json
{
  "id": "fbbf0f30-c8e8-4a5f-a9c7-2cf5b29b9a0d",
  "name": "Домашние дела"
}
```

Если категория не найдена:

* **Статус**: `404 Not Found`
* **Тело ответа**:

```json
{
  "detail": "Category not found"
}
```
